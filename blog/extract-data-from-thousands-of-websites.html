How to Extract Data From Thousands of Websites

How to design one scraping pipeline that extracts the same fields from thousands of different websites: input cleaning, concurrency, retries and reporting.

NSNithin Singh Published 2026-11-148 min readScale
Quick answer

To extract data from thousands of different websites, you build one pipeline that doesn't depend on any single layout. Clean the URL list first, use generic extraction rules (structured data, meta tags, contact pages and pattern matching), run requests concurrently with per-domain limits and retries, fall back to a headless browser only when needed, and log a status for every site.

Why this is a different problem

Scraping one website means writing selectors for one layout. Scraping five thousand websites means you can't write five thousand sets of selectors. The pipeline has to find the data wherever it lives, accept that some sites will fail, and tell you exactly which ones did and why.

Step 1: Clean the input list

  • Normalise URLs: add the scheme, lower-case the domain and strip tracking parameters.
  • Deduplicate by domain, since the same company is often listed with and without www.
  • Pre-check DNS and HTTP status to remove dead domains before the main run.

Step 2: Use layout-independent extraction

Look for data in places that are consistent across sites:

  • Structured data: JSON-LD such as Organization or LocalBusiness schema often holds names, addresses and phone numbers.
  • Meta tags: titles, descriptions and Open Graph data.
  • Likely pages: follow links containing words like contact, about or impressum, using local-language equivalents too.
  • Patterns: regular expressions for emails, phone numbers and social profile URLs, with validation to reject false positives.

Step 3: Run concurrently, but politely

With thousands of different domains, you can make many requests in parallel without overloading any single server. An async HTTP client (for example httpx with asyncio) or Scrapy handles this well. Set a timeout on every request, a small per-domain limit and a retry policy with back-off for transient errors.

sem = asyncio.Semaphore(50)   # global concurrency
async def fetch(client, url):
    async with sem:
        for attempt in range(3):
            try:
                r = await client.get(url, timeout=20, follow_redirects=True)
                return r.status_code, str(r.url), r.text
            except httpx.TransportError:
                await asyncio.sleep(2 ** attempt)
    return None, url, ""

Step 4: Fall back to a browser only when needed

Headless browsers are slow and resource-hungry. Use the fast HTTP path first, and send a site to Playwright only when the HTML comes back nearly empty or the expected fields are missing. In a typical mixed list, only a minority of sites need the browser.

Step 5: Checkpoint and report everything

  • Checkpointing: write results as you go so a crash doesn't restart the job.
  • Status per site: success, no data found, blocked, timeout or invalid domain.
  • Source evidence: record the URL where each value was found.

A transparent status column is what separates a professional deliverable from a spreadsheet with mysterious gaps. Once the data is collected, clean it with Pandas.

Frequently asked questions

How long does it take to scrape thousands of websites?

It depends on how many pages per site are visited, how many need a browser, and the rate limits used. A pipeline for a few thousand homepages and contact pages typically runs in hours, not days.

Why do some websites return no data?

Common reasons are dead domains, blocking, content loaded only by JavaScript, or the data simply not being published. A good pipeline labels each case.
